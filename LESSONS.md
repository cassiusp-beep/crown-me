# Lessons

## 2026-09-25 Crown Me: face-crop crown app (upload + webcam)

**Lessons learned**
- **The model learned the scenes, not the face.** Training used full screenshots, which Teachable Machine center-crops to a square. Testing showed the classifier recognizing *Cassius photos* more than *Cassius' face*. On `not_cassius` training photos, the whole-photo framing crowned 3 of 129 strangers, but face crops crowned 18 of 126, mostly at 97–100% confidence. Geirhos et al. call this "shortcut learning": the model uses whatever cue separates the training set, not the cue you intended. *Would change:* next time, build the training set with the same crop function the app uses (train/infer parity), before training.
- **Raising the confidence threshold can't fix a confidently wrong model.** Moving from 0.6 to 0.95 still crowned 11 strangers and started rejecting real Cassius photos. Confidence scores only help when the mistakes are uncertain ones. *Would change:* check whether the errors are low-confidence before reaching for a threshold.
- **Check the model's actual labels.** The exported metadata truncates labels (`cassius_happ...`). String equality against `cassius_happy` would have silently disabled every crown. *Would change:* print `getClassLabels()` as the first step of any Teachable Machine integration.
- **"Always returns something" models need their own presence check.** PoseNet returned a pose (score 0.40) for a face-only selfie. When the arms were out of the webcam frame, its guessed arm positions read as `arms_up` at 92%. A shoulders check didn't catch this. Requiring a visible wrist did (false sparkles 26/66 → 2/66 on webcam-like crops).
- **"Not recognized" can really mean "never detected".** In a group selfie, the debug view showed that Cassius' face never reached the classifier. The short-range detector had missed it. Scanning overlapping sections found it, and a zoom-in re-check removed the one false face this added across 330 photos. *Would change:* when a result looks wrong, check each stage (detect → crop → classify) separately before blaming the model.
- **The same framing mismatch showed up twice.** The pose model had it too: Teachable Machine trains on the center square, but the app passed whole photos. The classifier reads PoseNet's raw heatmap grid, so position in the square matters. arms_down accuracy went from 25/66 to 66/66 once the input was center-cropped. *Would change:* for any Teachable Machine model, find out how the trainer framed the images and copy that exactly, before testing anything else.

**Lenses applied**
- **Ethics / equity:** Commercial face classifiers have been shown to fail unevenly across skin type and gender (Buolamwini & Gebru). This model decides identity from 330 images of mostly a few people. That's fine for a crown, but the same design would be unacceptable anywhere a wrong "yes" had consequences. Of the two errors, crowning a stranger is the one this app's users will notice most.
- **Design (choice or habit):** The spec's "tight face crop" was a sensible habit borrowed from face-recognition practice, but it didn't match how this model was actually trained. The data, not the convention, should have set the crop. The `?debug=1` crop thumbnails made the mismatch visible.
- **Systems:** MediaPipe's detector is the *short-range* BlazeFace model, so the pipeline is built for selfies and close portraits. Small faces in group shots are both missed by detection and, when they are found, upscaled into blurry crops the classifier has never seen. That's the likeliest source of future false positives.

**Worth exploring next**
- Retrain the image model on 224×224 crops generated by the app's own `cropFace` (the debug thumbnails show exactly what they look like), then "Update my cloud model" to keep the same URL. Re-run the 330-image test and see if the spec's 15% padding and 0.6 threshold work again.
- Split identity from expression: a face-embedding match against a few reference photos for "is this Cassius?", and Teachable Machine only for happy vs. neutral.
- Skip faces below a minimum pixel size instead of classifying blurry upscaled crops.

**Sources**
- [Shortcut Learning in Deep Neural Networks, Geirhos et al., 2020](https://arxiv.org/abs/2004.07780): names the failure mode seen here, a model relying on an unintended cue that works on training data.
- [Gender Shades, Buolamwini & Gebru, FAT* 2018](https://proceedings.mlr.press/v81/buolamwini18a.html): error rates up to 34.7% for darker-skinned women vs. 0.8% for lighter-skinned men in commercial face classifiers. A reminder that face models fail unevenly.
- [MediaPipe Face Landmarker docs](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker): the detector is the "BlazeFace short-range model", which explains missed small or distant faces.
- [teachablemachine-community, `libraries/image/src/custom-mobilenet.ts`](https://github.com/googlecreativelab/teachablemachine-community/blob/master/libraries/image/src/custom-mobilenet.ts): `predict()` center-crops every input to the model's `imageSize` (224) with `cropTo`, so the framing the model sees depends on the input's aspect ratio.

*Everything above other than the source descriptions is my interpretation, based on tests run on the project's own training images. Those tests are optimistic because the model had seen those images during training.*
